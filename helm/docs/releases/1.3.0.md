## [1.3.0](https://github.com/Cloudzero/cloudzero-agent/compare/v1.2.14...v1.3.0) (2026-10-01)

Release 1.3.0 marks Grafana Alloy (clustered mode) as stable, improves Alloy
horizontal scaling, and includes dependency and reliability updates. The
KubeState plugin remains experimental.

### Highlights

- **Alloy is stable**: `components.agent.mode: clustered` is no longer marked
  experimental. Alloy remains an alternative to Prometheus for metrics
  collection; default installs continue to use Prometheus unless clustered
  mode is selected.

- **Alloy work sharding**: Alloy replicas now form a cluster and shard scrape
  and processing work across peers (CP-47394). Horizontal scaling in clustered
  mode is effective for workload distribution, not only for capacity headroom.

- **Bundled Alloy image**: The agent image embeds CloudZero Alloy
  `v1.19.2-patch-1` (CP-47350). <!-- TODO: update if 1.20.1 rebase lands before cut -->

### Experimental Features

The following features remain experimental and may change in future releases:

- **KubeState Plugin**: Replace the kube-state-metrics subchart with the
  embedded Alloy KubeState plugin (`components.agent.kubeState.enabled: true`
  in clustered mode).

- **Optional webhook server disable**: `components.webhookServer.enabled: false`
  remains intended for KubeState-based topologies and is not recommended for
  general use.

### Reliability and Testing

- **Clustered kuttl diagnostics**: Install failures in the Alloy clustered
  kuttl suite are easier to diagnose (CP-47363).

- **Smoke tests**: MinIO for smoke tests is pulled from Chainguard instead of
  Docker Hub (CP-48635).

### Dependency Updates

- Routine Dependabot updates across Go modules, container base images, Helm
  tooling, and GitHub Actions (CP-29639). See the compare link above for the
  full list.

### Upgrade Steps

To upgrade to version 1.3.0, run the following command:

```sh
helm upgrade --install <RELEASE_NAME> cloudzero/cloudzero-agent -n <NAMESPACE> --create-namespace -f configuration.example.yaml --version 1.3.0
```

No configuration changes are required for existing Prometheus-mode installs.
Customers already using `components.agent.mode: clustered` should expect
sharding behavior across replicas after upgrade; review replica counts and HPA
settings if you previously over-scaled to compensate for missing sharding.
